# 보유/실현 손익 화면 설명서

## 1. 화면의 현재 성격

현재 "보유/실현 손익" 화면은 단일 화면 안에 여러 분석 기능이 섞여 있는 복합 분석 페이지다. 단순히 보유 종목의 평가손익을 보여주는 화면이 아니라, 다음 기능들이 한 페이지에 함께 존재한다.

- 현재 보유 종목 평가
- 종목별 현재가 조회 및 평가손익 계산
- 과거 매수 타이밍 회고 분석
- 종목별 매수 회고 랭킹
- 매수 시점별 상세 사후 성과 분석
- 실현손익 요약
- 실현손익 상세 내역
- 계산 경고 및 데이터 품질 상태 표시

즉, 현재 화면은 "포트폴리오 상태 확인", "과거 투자 행동 회고", "매도 성과 정산"이 한 화면에 합쳐진 상태다. 사용자가 빠르게 현재 상태만 보고 싶은 경우에도 과거 회고/실현손익 테이블이 같이 노출되고, 반대로 과거 매수 판단을 분석하고 싶은 경우에도 보유 평가/실현손익 정보가 시각적 노이즈가 된다.

## 2. 이 화면이 다루는 핵심 질문

현재 화면은 사용자의 투자 데이터를 바탕으로 크게 4가지 질문에 답하려고 한다.

1. 지금 내가 무엇을 얼마나 보유하고 있는가?
2. 현재 보유 종목은 손익 기준으로 어떤 상태인가?
3. 과거 매수 판단은 결과적으로 좋았는가, 나빴는가?
4. 이미 매도한 거래에서 실제로 얼마를 벌거나 잃었는가?

이 네 질문은 모두 중요하지만, 사용 목적과 시간축이 다르다.

- 1, 2번은 현재 상태 분석이다.
- 3번은 과거 행동 평가다.
- 4번은 확정 손익 정산이다.

따라서 하나의 화면에 모두 넣기보다는 목적별로 화면을 나누는 것이 적합하다.

## 3. 현재 화면의 주요 데이터 출처

현재 화면은 주로 legacy `Transaction` 데이터를 기반으로 계산된다.

### 3.1 거래 원장

기본 거래 데이터는 `portfolio.Transaction`이다.

주요 필드:

- 매매구분: 매수 / 매도
- 종목명
- 거래일시
- 수량
- 단가

이 거래 원장을 순서대로 읽어 보유 수량, 평균매수가, 실현손익을 계산한다.

### 3.2 종목 매핑

거래 원장의 종목명은 `portfolio.StockSymbol` 또는 `stocks.Stock`과 연결된다.

목적:

- 종목명과 실제 종목 master 연결
- 가격 조회용 ticker 확보
- DailyPrice 또는 yfinance 가격 조회 연결

### 3.3 현재가

현재 보유 분석은 `get_price_snapshot()`을 통해 가격을 조회한다.

현재 구현상 다음 흐름이다.

- `StockSymbol`에서 ticker 조회
- yfinance에서 `fast_info` 또는 history 조회
- 현재가, 전일 종가, 통화, 오류 상태 반환

이 가격은 실시간 Toss 가격이 아니라 legacy 가격 조회 흐름이다. 따라서 "실시간 계좌 평가"라기보다는 "저장/외부 가격 기반의 보유 평가"에 가깝다.

### 3.4 DailyPrice

과거 추가 매수 회고 분석은 `marketdata.DailyPrice`를 사용한다.

역할:

- 매수일 이후 5/20/60거래일 성과 계산
- 매수 이후 20일 내 최대 상승률 계산
- 매수 이후 20일 내 최대 낙폭 계산
- 저점 도달일, 고점 도달일, 손익분기 도달일 계산
- 매수 후 가격 흐름 sparkline 생성

## 4. 현재 화면의 구성 요소

## 4.1 보유 분석 섹션

### 목적

현재 보유 중인 종목의 평가 상태를 한눈에 보여준다.

### 현재 표시 항목

- 종목
- 티커
- 보유수량
- 평균매수가
- 현재가
- 장부가
- 평가금액
- 평가손익
- 수익률
- 상태

### 사용자가 얻을 수 있는 답

- 어떤 종목을 아직 들고 있는가?
- 각 종목의 보유 수량은 얼마인가?
- 평균매수가 대비 현재가가 어떤 상태인가?
- 평가손익이 플러스인지 마이너스인지?
- 가격 조회가 정상인지, 실패했는지?

### 성격

이 섹션은 "현재 보유 상태 대시보드"에 해당한다. 사용자는 매일 가장 먼저 보고 싶은 정보일 가능성이 높다.

### 문제점

- 티커/코드 같은 기술적 값이 노출되면 사용자는 종목을 외워야 한다.
- 가격 조회 실패가 내부 예외 문자열로 표시되면 사용자 경험이 나쁘다.
- 상세한 회고 분석과 같은 화면에 있어 시각적으로 묻힌다.

### 분리 권장

별도 화면 또는 상단 핵심 카드로 분리하는 것이 적합하다.

추천 화면명:

- 현재 보유 평가
- 보유 종목 평가
- 내 보유 현황

## 4.2 과거 추가 매수 회고 분석 섹션

### 목적

과거 매수 거래가 결과적으로 좋은 타이밍이었는지 사후 분석한다.

단순 손익 계산이 아니라, 매수 이후 일정 기간 동안 주가가 어떻게 움직였는지를 평가한다.

### 현재 컨트롤

- 종목 선택
- 판정 필터
  - 전체
  - 잘한 매수
  - 보통 매수
  - 아쉬운 매수
  - 판단 보류
- 랭킹 정렬
  - 평균 회고 점수
  - 실행 일관성
  - 좋은 매수 비율
  - 평균 20일 성과
- 회고 분석 실행
- CSV 다운로드

### 분석 기준

거래일 기준으로 다음 데이터를 비교한다.

- 5거래일 후 성과
- 20거래일 후 성과
- 60거래일 후 성과
- 20거래일 내 최대 상승
- 20거래일 내 최대 하락
- 매수 전 평균단가 대비 매수가
- 매수 직전 5일 등락률
- 저점 도달까지의 거리
- 손익분기 도달일
- 최고점 도달일

### 사용자가 얻을 수 있는 답

- 내가 추가 매수를 잘한 종목은 무엇인가?
- 반복적으로 안 좋은 타이밍에 매수한 종목은 무엇인가?
- 물타기 판단이 실제로 효과가 있었는가?
- 매수 후 바로 반등했는가, 더 빠졌는가?
- 어떤 종목에서 실행 일관성이 좋은가?
- 어떤 종목은 매수 판단을 보류해야 하는가?

### 성격

이 섹션은 "투자 행동 회고/학습" 화면이다. 현재 손익보다 과거 의사결정 품질을 분석하는 용도다.

### 문제점

- 정보량이 매우 많다.
- 랭킹, 요약, 차트, 상세 테이블이 한 섹션 안에 모두 들어 있다.
- 보유 분석이나 실현손익과 목적이 다르다.
- 초보 사용자는 "무엇을 먼저 봐야 하는지" 알기 어렵다.

### 분리 권장

별도 화면으로 분리하는 것이 강력히 권장된다.

추천 화면명:

- 매수 타이밍 회고
- 추가매수 회고 분석
- 투자 행동 분석
- 과거 매수 판단 리포트

## 4.3 종목별 회고 랭킹

### 목적

여러 종목을 비교해 어떤 종목에서 매수 판단이 좋았는지 순위를 보여준다.

### 현재 표시 항목

- 순위
- 종목
- 평균 회고 점수
- 평균 20일 성과
- 잘한 매수 건수
- 아쉬운 매수 건수
- 평가 완료 건수
- 신뢰도
- 일관성
- 각종 1위 badge
  - 현재 정렬 1위
  - 평균 점수 1위
  - 좋은 비율 1위
  - 20일 성과 1위
  - 회복 속도 1위
  - 저점 근접도 1위
  - 일관성 1위

### 사용자가 얻을 수 있는 답

- 어떤 종목에서 내가 매수를 잘했는가?
- 어떤 종목은 반복적으로 타이밍이 나쁜가?
- 성과는 좋지만 표본이 적은 종목은 무엇인가?
- 일관성이 좋은 종목과 운 좋게 한 번 잘 된 종목을 구분할 수 있는가?

### 성격

이 기능은 종목별 투자 습관 비교 화면이다.

### 문제점

- 랭킹만 보고 싶은 사용자는 상세 매수 테이블까지 같이 보게 된다.
- 화면 상단에서 너무 많은 badge와 설명이 노출되어 복잡하다.
- 사용자가 "랭킹"과 "선택 종목 상세 분석"의 관계를 직관적으로 이해하기 어렵다.

### 분리 권장

회고 분석 화면 안의 하위 탭으로 분리하는 것이 좋다.

추천 구조:

- 탭 1: 요약
- 탭 2: 종목별 랭킹
- 탭 3: 선택 종목 상세
- 탭 4: 매수별 상세 로그

## 4.4 전체 가격 흐름과 매수 시점 차트

### 목적

선택한 종목의 가격 흐름 위에 과거 매수 시점을 표시한다.

### 현재 표시 항목

- 전체 가격 흐름 line chart
- 매수 시점 marker
- marker 색상
  - 잘한 매수
  - 보통 매수
  - 아쉬운 매수
  - 판단 보류
- 저점/고점/최근 종가
- 날짜 범위

### 사용자가 얻을 수 있는 답

- 내가 주가가 오르기 전에 샀는가?
- 하락 중 너무 일찍 샀는가?
- 반복적으로 같은 구간에서 매수했는가?
- 추가매수 시점이 저점에 가까웠는가?

### 성격

시각적 회고 도구다. 숫자 테이블보다 직관적인 학습에 적합하다.

### 문제점

- 현재는 회고 분석 섹션 안에 포함되어 있어 중요도가 묻힐 수 있다.
- 차트가 단순 SVG라 상호작용은 제한적이다.
- marker 설명은 hover title에 의존한다.

### 분리 권장

선택 종목 상세 화면의 핵심 영역으로 배치하는 것이 좋다.

추천 구성:

- 상단: 종목명, 분석 기간, 가격 데이터 수
- 중앙: 가격 흐름 + 매수 marker
- 하단: 선택 marker 상세 정보
- 우측: 요약 지표

## 4.5 회고 인사이트 요약

### 목적

상세 테이블을 보지 않아도 선택 종목의 매수 품질을 요약한다.

### 현재 표시 항목

- headline
- 평균 20거래일 성과
- 평균 20일 최대 낙폭
- 가장 자주 나온 매수 구분
- best case summary
- worst case summary

### 사용자가 얻을 수 있는 답

- 이 종목에서는 내 매수 판단이 전반적으로 좋았나?
- 평균적으로 매수 후 수익이 났나?
- 매수 후 더 크게 빠지는 경향이 있었나?
- 어떤 상황에서 좋은 매수가 나왔나?
- 어떤 상황에서 아쉬운 매수가 나왔나?

### 성격

요약 리포트다. 사용자가 처음 봐야 할 정보다.

### 문제점

- 현재는 랭킹, 차트, 카운트 뒤에 배치되어 있어 핵심 요약인데도 늦게 나온다.
- 사용자의 행동 방향으로 연결되는 설명이 부족할 수 있다.

### 분리 권장

회고 분석 상세 화면의 상단 핵심 카드로 배치해야 한다.

## 4.6 사유 유형 요약

### 목적

매수 평가가 좋거나 나빴던 원인을 유형별로 집계한다.

### 예시 사유

- 매수 후 반등
- 추가 하락
- 성과 혼조
- 데이터 부족
- 저점 근접
- 손익분기 미도달

### 사용자가 얻을 수 있는 답

- 내 나쁜 매수는 주로 어떤 이유로 발생했는가?
- 좋은 매수는 어떤 공통 패턴이 있었는가?
- 반복되는 실수 유형은 무엇인가?

### 성격

행동 개선 인사이트다.

### 분리 권장

"회고 인사이트"의 하위 영역으로 배치하면 좋다.

## 4.7 실행 품질 지표

### 목적

매수 실행의 정량 품질을 평가한다.

### 현재 표시 항목

- 평균 종합 회고 점수
- 매수 직전 5일 평균 등락률
- 이전 평단 대비 평균 매수가
- 평균 저점 대비 추가 하락
- 평균 저점 도달일
- 평균 손익분기 도달일
- 평균 최고점 도달일

### 사용자가 얻을 수 있는 답

- 나는 하락 직후 매수하는가, 상승 중 매수하는가?
- 기존 평단보다 충분히 낮게 추가매수했는가?
- 매수 후 더 빠지는 구간이 자주 있었는가?
- 손익분기까지 평균 며칠 걸리는가?
- 매수 후 고점이 빨리 오는가?

### 성격

투자 습관 측정 지표다.

### 문제점

- 지표 이름이 많고 난도가 높다.
- 사용자가 해석하기 어렵다.
- 도움말 또는 해석 문구가 필요하다.

### 분리 권장

고급 분석 섹션으로 접거나 별도 탭으로 빼는 것이 좋다.

## 4.8 점수 비교 사례

### 목적

가장 좋았던 매수와 가장 아쉬웠던 매수를 비교한다.

### 현재 표시 항목

- 가장 좋았던 매수
  - 거래 시각
  - 매수 구분
  - 점수
  - 20일 성과
  - 평가 요약
- 가장 아쉬웠던 매수
  - 거래 시각
  - 매수 구분
  - 점수
  - 20일 성과
  - 평가 요약

### 사용자가 얻을 수 있는 답

- 좋은 매수와 나쁜 매수의 차이가 무엇인가?
- 다음 매수 때 피해야 할 패턴은 무엇인가?
- 성공 사례를 반복하려면 어떤 조건을 봐야 하는가?

### 성격

학습용 비교 리포트다.

### 분리 권장

회고 상세 화면의 "대표 사례" 카드로 유지하면 좋다.

## 4.9 매수별 상세 회고 테이블

### 목적

각 매수 거래별로 사후 성과를 자세히 보여준다.

### 현재 표시 항목

- 매수시각
- 매수 구분
- 수량
- 매수가
- 매수 전 평단
- 매수 후 평단
- 5일 후 성과
- 20일 후 성과
- 60일 후 성과
- 20일 최대상승
- 20일 최대하락
- 판정
- 평가 요약
- 타이밍 점수
- 직전 5일 흐름
- 이전 평단 대비 차이
- 저점까지의 거리
- 손익분기 도달일
- 최고점 도달일
- sparkline

### 사용자가 얻을 수 있는 답

- 특정 날짜의 매수는 결과적으로 어땠는가?
- 그 매수가 물타기였는가, 신규 진입이었는가?
- 매수 후 몇 일 뒤 반등했는가?
- 매수 후 바로 더 빠졌는가?
- 결과적으로 잘한 매수인가, 아쉬운 매수인가?

### 성격

상세 로그다. 전문가용 또는 검증용 정보다.

### 문제점

- 테이블 컬럼이 매우 많다.
- 모바일에서 보기 어렵다.
- 초보 사용자에게는 압도적이다.
- 상단 요약보다 상세 로그가 너무 큰 비중을 차지한다.

### 분리 권장

기본 화면에서는 숨기고 "상세 거래 보기" 또는 "CSV 다운로드" 중심으로 제공하는 것이 좋다.

## 4.10 실현손익 요약

### 목적

이미 매도한 거래에서 확정된 손익을 보여준다.

### 현재 표시 항목

- 총 실현 매도수량
- 총 매도금액
- 총 매도원가
- 총 실현손익
- 총 실현손익률

### 사용자가 얻을 수 있는 답

- 지금까지 매도로 확정된 손익은 얼마인가?
- 매도한 총 금액은 얼마인가?
- 매도한 종목의 원가는 얼마였는가?
- 실현손익률은 얼마인가?

### 성격

확정 성과 요약이다. 세금/손익 기록 관점에서 중요하다.

### 문제점

- 현재 보유손익과 같은 화면에 있어 평가손익과 실현손익이 혼동될 수 있다.
- 사용자는 "현재 손익"과 "확정 손익"을 명확히 구분해야 한다.

### 분리 권장

별도 화면으로 분리해야 한다.

추천 화면명:

- 실현손익
- 매도 손익
- 확정 손익 리포트

## 4.11 종목별 실현손익

### 목적

- 종목별 확정 손익 규모는 얼마인가?

### 성격

실현손익 집계 테이블이다.

### 분리 권장

실현손익 화면의 메인 테이블로 적합하다.

## 4.12 실현손익 계산 상세

### 목적

각 매도 거래가 어떤 평균매수가 기준으로 손익 계산되었는지 보여준다.

### 현재 표시 항목

- 매도시각
- 종목
- 매도수량
- 매도가
- 평균매수가
- 매도금액
- 매도원가
- 실현손익
- 수익률
- 비고

### 사용자가 얻을 수 있는 답

- 특정 매도 거래의 손익은 어떻게 계산되었는가?
- 평균매수가가 얼마였는가?
- 일부 매도만 계산되었는가?
- 보유수량이 부족한 매도 거래가 있었는가?

### 성격

감사/검증용 상세 내역이다.

### 문제점

- 일반 사용자는 요약만 원할 가능성이 높다.
- 테이블이 길어지면 화면 가독성이 크게 떨어진다.

### 분리 권장

실현손익 화면 안에서 접이식 상세 테이블로 제공하거나 별도 "계산 상세" 탭으로 분리한다.

## 5. 현재 화면의 핵심 문제

## 5.1 서로 다른 목적의 기능이 한 화면에 섞여 있음

현재 화면은 다음 3개 목적이 섞여 있다.

- 현재 보유 평가
- 과거 매수 행동 회고
- 매도 실현손익 정산

이 세 기능은 사용자의 질문, 시간축, 필요한 상세 수준이 다르다.

## 5.2 테이블이 너무 많음

현재 화면에는 최소 다음 테이블들이 있다.

- 보유 분석 테이블
- 종목별 회고 랭킹 테이블
- 매수별 회고 상세 테이블
- 종목별 실현손익 테이블
- 실현손익 계산 상세 테이블

여기에 KPI 카드, 차트, 인사이트, 사유 요약, 실행 품질 지표까지 함께 존재한다. 결과적으로 사용자가 원하는 정보를 찾기 어렵다.

## 5.3 초보자와 고급 사용자의 요구가 섞임

초보 사용자는 다음 정보만 먼저 보고 싶을 수 있다.

- 지금 수익인가 손실인가?
- 어떤 종목이 문제인가?
- 매도해서 번 돈은 얼마인가?

반면 고급 사용자는 다음을 보고 싶다.

- 매수 타이밍 점수
- 20일 최대 낙폭
- 저점 도달일
- 손익분기 도달일
- 랭킹 정렬
- 상세 CSV

현재는 두 사용자층이 같은 화면에서 같은 밀도의 정보를 보게 된다.

## 5.4 평가손익과 실현손익의 개념 구분이 약함

평가손익은 아직 매도하지 않은 보유 종목의 미실현 손익이다.

실현손익은 이미 매도해서 확정된 손익이다.

이 둘은 투자 판단에서 완전히 다른 의미를 갖는다. 같은 화면에 있을 수는 있지만, 명확히 분리된 영역과 설명이 필요하다.

## 5.5 회고 분석은 독립 기능으로 성장할 수 있음

과거 추가 매수 회고 분석은 기능적으로 매우 크다. 사실상 독립된 "투자 행동 분석" 모듈이다. 현재 보유/실현손익 화면 안에 들어가기에는 정보량이 많다.

## 8. 각 화면의 목표 정의

## 8.1 손익 대시보드의 목표

사용자가 10초 안에 다음을 알 수 있어야 한다.

- 전체적으로 돈을 벌고 있는가, 잃고 있는가?
- 미실현 손익과 실현 손익은 각각 얼마인가?
- 가장 문제가 되는 종목은 무엇인가?
- 더 자세히 봐야 할 영역은 어디인가?

## 8.2 현재 보유 평가 화면의 목표

사용자가 현재 보유 종목에 대해 다음 결정을 할 수 있어야 한다.

- 어떤 종목을 우선 점검해야 하는가?
- 손실률이 큰 종목은 무엇인가?
- 추가매수/컨설팅 검토가 필요한 종목은 무엇인가?
- 가격 데이터가 누락된 종목은 무엇인가?

단, 이 화면은 매수/매도 추천을 하지 않아야 한다. 데이터 기반 상태 확인 화면이어야 한다.

## 8.3 실현손익 화면의 목표

사용자가 과거 매도 결과를 정확히 검증할 수 있어야 한다.

- 실제 확정 수익/손실은 얼마인가?
- 어떤 종목에서 수익이 났는가?
- 어떤 매도에서 손실이 확정되었는가?
- 계산에 경고가 있는 거래는 무엇인가?

## 8.4 매수 회고 화면의 목표

사용자가 자신의 매수 습관을 학습할 수 있어야 한다.

- 나는 너무 일찍 물타기를 하는가?
- 하락 추세에서 반복적으로 매수하는가?
- 매수 후 평균적으로 며칠 뒤 반등하는가?
- 좋은 매수는 어떤 조건에서 나왔는가?
- 다음 매수 때 피해야 할 패턴은 무엇인가?

## 8.5 회고 랭킹 화면의 목표

사용자가 종목별로 자신의 매수 판단 품질을 비교할 수 있어야 한다.

- 어떤 종목에서 매수 판단이 좋았는가?
- 어떤 종목은 반복적으로 실패했는가?
- 표본이 충분한 종목과 부족한 종목은 무엇인가?
- 향후 분석 우선순위를 어디에 둘 것인가?

## 10. 화면 정리 우선순위

## 10.1 1순위: 보유 평가와 실현손익 분리

가장 먼저 해야 할 일은 현재 보유 평가와 실현손익을 분리하는 것이다.

이유:

- 평가손익과 실현손익은 사용자에게 혼동되기 쉽다.
- 두 영역은 시간축이 다르다.
- 둘 다 독립적으로 자주 확인할 수 있다.

## 10.2 2순위: 회고 분석 독립 화면화

과거 추가 매수 회고 분석은 별도 화면으로 빼야 한다.

이유:

- 기능량이 많다.
- 테이블과 차트가 많다.
- 분석 목적이 "현재 손익 확인"과 다르다.

## 10.3 3순위: 상세 테이블 접기

매수별 상세 회고 테이블과 실현손익 계산 상세 테이블은 기본 접힘 상태가 좋다.

이유:

- 일반 사용자는 요약을 먼저 원한다.
- 상세 테이블은 검증/디버깅용 성격이 강하다.
- 모바일 가독성이 떨어진다.

## 10.4 4순위: 코드/티커 노출 최소화

사용자는 종목코드를 외우고 싶지 않다.

표시 원칙:

- 기본 표시는 종목명
- 코드는 숨김 또는 보조 정보
- 검색은 종목명 중심
- 내부 API 호출이나 URL에는 코드 사용 가능
- 코드가 꼭 필요하면 "상세" 또는 tooltip 수준으로만 제공

## 11. GPT Pro에 요청할 수 있는 설계 방향

아래 요구사항을 GPT Pro에 전달하면 된다.

### 요청 문장 예시

theStock의 현재 "보유/실현 손익" 화면은 보유 평가, 과거 매수 회고, 종목별 회고 랭킹, 실현손익 요약, 실현손익 상세가 한 화면에 섞여 있어 정보 밀도가 너무 높습니다. 사용자가 종목코드를 외울 필요 없이 종목명 중심으로 이해할 수 있고, 현재 보유 상태와 확정 실현손익, 과거 매수 행동 회고를 명확히 구분할 수 있도록 화면 구조를 재설계해 주세요.

다음 기준을 반영해 주세요.

- 평가손익과 실현손익을 구분
- 현재 상태 확인과 과거 행동 회고를 분리
- 요약 먼저, 상세는 접거나 별도 탭
- 종목코드는 기본적으로 숨기고 종목명 중심
- 초보 사용자는 핵심 손익만 빠르게 이해
- 고급 사용자는 상세 회고/랭킹/CSV 다운로드 가능
- 모바일에서도 과도한 wide table이 나오지 않도록 구성
- 매수/매도 추천처럼 보이지 않게 read-only 분석 화면으로 설계
- 전체적으로 Django Template + Bootstrap/Tailwind-like card/table UI에 적합한 구조로 제안

## 12. 추천 화면 IA

최종 추천 IA는 다음과 같다.

```text
손익 분석

│  ├─ 전체 실현손익
│  ├─ 손실 상위 보유 종목

│
├─ 보유 평가
│  ├─ 보유 종목 KPI
│  ├─ 보유 종목 테이블
│  ├─ 가격 조회 상태
│  └─ 컨설팅/상세 분석 링크

│  ├─ 종목 선택
```

## 13. 핵심 설계 원칙

1. 첫 화면은 "판단"이 아니라 "상태 파악"에 집중한다.
2. 현재 보유와 과거 매도는 분리한다.
3. 과거 매수 회고는 독립 분석 도구로 다룬다.
4. 상세 테이블은 기본 노출하지 않는다.
5. 종목명 중심으로 표시한다.
6. 숫자 지표에는 해석 문구를 붙인다.
7. 오류 메시지는 내부 예외가 아니라 사용자 친화적인 상태로 표시한다.
8. read-only 분석 화면임을 명확히 한다.
9. 매수/매도 추천처럼 보이는 문구를 피한다.
10. 사용자가 다음 행동을 선택할 수 있도록 상세 화면 링크를 제공한다.

## 14. 최종 목표

이 화면 개편의 최종 목표는 "많은 데이터를 한 번에 보여주는 화면"이 아니라, 사용자의 질문에 따라 적절한 깊이로 들어갈 수 있는 분석 시스템을 만드는 것이다.

사용자는 처음에는 다음만 알면 된다.

- 지금 보유 손익은 어떤가?
- 실현 손익은 어떤가?
- 문제가 큰 종목은 무엇인가?

그 다음 필요할 때만 깊게 들어간다.

- 왜 이 종목의 손익이 나쁜가?
- 과거 매수 타이밍은 좋았는가?
- 어떤 종목에서 반복적으로 실수했는가?
- 어떤 매도에서 손익이 확정되었는가?

따라서 "보유/실현 손익" 화면은 단일 거대 테이블 페이지가 아니라, 손익 대시보드와 세부 분석 화면들의 출발점으로 재구성되어야 한다.
