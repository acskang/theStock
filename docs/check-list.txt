  02 Scoring Engine 기준으로 남아 있는 것

  - 스코어링 엔진은 동작하지만 규칙 기반 휴리스틱입니다. 실전 성능 검증이나 파라미터 튜닝은 아직 없습

  - 외부 데이터 수집기가 없어서 DailyPrice, InvestorFlow, MarketIndex, RiskEvent를 수동/seed로 넣어야

  - 기술지표 계산 결과를 별도 캐시/저장하지 않기 때문에, 향후 데이터 규모가 커지면 반복 계산 비용이 생

  03 API Workflow 기준으로 남아 있는 것

  - evaluate는 저장되지만, probability와 consult는 현재 비저장성 계산 API입니다. 결과 이력, 감사 추적,
    비교 분석이 필요하면 별도 저장 모델이 추가로 필요합니다.
  - API는 동작하지만 OpenAPI/Swagger 같은 계약 문서가 없습니다. 외부 소비자가 붙기 시작하면 응답 스키
    마 관리가 부담이 됩니다.
  - 인증 방식이 SessionAuthentication/BasicAuthentication 중심이라 서비스형 API로 쓰기에는 제한적입니
    다. 토큰/JWT, rate limiting, audit log 강화가 후속 과제입니다.

  05 Probability Engine 기준으로 남아 있는 것

  - 확률 엔진의 historical component는 설계서의 완전한 feature-distance 방식이 아니라 pragmatic
    fallback입니다. 즉, “동작하는 1차 버전”이지 고도화 버전은 아닙니다.
  - 확률 결과도 데이터 품질에 민감합니다. 시장/수급/가격 이력이 부족하면 확률은 계산되더라도 신뢰도가
    낮아집니다.
  - 확률 결과 저장, 확률 이력 조회, 확률 비교 리포트는 아직 없습니다.
